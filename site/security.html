Security

An extension that runs on every page is a target. These are the measures in version {{VERSION}}, and what they do and do not cover.

Hostile web pages

  • Pages can't talk to the extension. It declares no external messaging, so web pages and other sites have no channel to it. The page-side detector sends one-way notes to the extension's own script, and every note is verified to come from the same window before it is used.
  • The detector can only watch. It reads the content type and file size of responses the page already made. It never changes a request or response, reads no bodies or cookies, and sends nothing to any server.
  • Only extension pages can change state. Settings, downloads, the saved list and erase are accepted only from the extension's own popup, side panel and settings page, checked by origin on every message.
  • The background re-checks every download. The address must be http or https, must be one the extension itself found on a page (or one you already accepted), and must not be protected. File names are forced inside your Downloads folder. A modified popup can't skip this.
  • Playlists are treated as hostile input. Only web addresses are fetched (never blob:, data:, file: or javascript:), the size and number of pieces are capped, and encrypted or live streams are refused before any piece is fetched.
  • Names and text from pages are only ever shown as text. Nothing is inserted as HTML, and the code contains no eval or dynamic script creation.

The extension itself

  • Strict content security policy: extension pages run only bundled scripts. No remote code, no inline script, no plugins, no changing the base address, no framing.
  • No remote code, ever. Everything that runs ships inside the package you installed. The fonts are bundled, not fetched.
  • Minimal reach beyond page scanning. No cookies, history, tabs-wide, webRequest or nativeMessaging permission is requested.
  • The preview is opt-in so opening the popup never contacts a stream's server.

Supply chain and releases

  • Releases are built in CI from a locked dependency list with npm ci. The production dependencies are checked against the public advisory database on every build.
  • Each release publishes SHA-256 checksums. The source of each release is included so Mozilla's reviewers, and you, can rebuild it.
  • Dependency updates are proposed automatically and go through the same tests before they are accepted.

This website

  • Static files only: no server code, no database, no login, nothing to inject into.
  • A strict content security policy that allows no scripts at all, plus frame-ancestors 'none', no referrer, no MIME sniffing and a locked-down permissions policy.
  • Served over HTTPS only. No third-party requests of any kind.
  • The local file tools are separate downloads. They run from a file you unzipped, with connect-src 'none', and they only read files you pick.

What it does not protect against

  • A page can show a fake stream. Download it and you get what that page serves, the same as clicking its link. The extension decides where files go and refuses protected or unusual ones, but it can't tell you whether a file is wise to open.
  • A compromised browser or operating system can read anything the extension stores.
  • Stores and browsers are the root of trust for updates. Install only from a store listing we link from this site, or verify the checksum.

Report a vulnerability

Email us with steps to reproduce. Please give us a reasonable time to fix it before you publish. We will acknowledge your report, keep you updated, and credit you if you wish. Details are also in security.txt.
